CATALOGUE DES URL ET COMMANDES API SHOPIFY POUR GÉRER UNE BOUTIQUE
Version de référence Shopify : 2026-07
Date de compilation : 2026-07-24

IMPORTANT
- L'Admin GraphQL API est l'interface principale recommandée par Shopify.
- L'Admin REST API est une API héritée depuis le 1er octobre 2024. Elle reste documentée,
  mais les nouvelles applications publiques doivent utiliser GraphQL et plusieurs ressources REST
  sont dépréciées ou limitées.
- GraphQL utilise UNE SEULE URL pour des centaines de requêtes et mutations. Le nom de la
  commande est envoyé dans le corps JSON; il ne crée pas une URL différente.
- Certaines fonctions exigent Shopify Plus, Shopify Payments, des scopes protégés, une approbation
  Shopify, un type d'application particulier ou l'activation d'une fonction dans la boutique.
- Les identifiants entre accolades doivent être remplacés par des valeurs réelles.
- La disponibilité exacte d'une commande doit toujours être validée par introspection du schéma
  GraphQL 2026-07 et par les scopes réellement accordés à l'application.

VARIABLES UTILISÉES
{shop} = sous-domaine de la boutique, sans https://, par exemple ma-boutique
{storefront_domain} = domaine public de la vitrine ou domaine myshopify.com
{id}, {product_id}, {order_id}, etc. = identifiants Shopify
{locale} = préfixe de langue, par exemple fr, fr-ca ou en
{access_token} = jeton d'accès Admin, Storefront ou Customer Account approprié
{callback_url} = URL HTTPS appartenant à votre application

EN-TÊTES PRINCIPAUX
Admin GraphQL/REST : X-Shopify-Access-Token: {access_token}
Storefront privé : X-Shopify-Storefront-Access-Token: {storefront_access_token}
Customer Account : Authorization: {customer_access_token}
GraphQL : Content-Type: application/json

1. AUTHENTIFICATION, OAUTH, DÉCOUVERTE ET PORTÉES
====================================================================================================
[ACTUEL] GET     https://{shop}.myshopify.com/admin/oauth/authorize?client_id={client_id}&scope={scopes}&redirect_uri={redirect_uri}&state={state}
          Démarre l'autorisation OAuth d'une application par le marchand.
[ACTUEL] POST    https://{shop}.myshopify.com/admin/oauth/access_token
          Échange un code OAuth, des identifiants client ou un subject token pris en charge contre un jeton d'accès Admin.
[ACTUEL] GET     https://{shop}.myshopify.com/admin/oauth/access_scopes.json
          Retourne les scopes actuellement associés au jeton Admin.
[ACTUEL] GET     https://{storefront_domain}/.well-known/openid-configuration
          Découvre dynamiquement les URL Customer Account OAuth/OIDC : authorization_endpoint, token_endpoint, end_session_endpoint et autres métadonnées.
[DYNAMIQUE] GET     {authorization_endpoint}?client_id={client_id}&response_type=code&redirect_uri={redirect_uri}&scope=openid%20email%20customer-account-api:full&state={state}&nonce={nonce}&code_challenge={challenge}&code_challenge_method=S256
          URL dynamique obtenue par OpenID Discovery; authentifie le client avec OAuth 2.0/OIDC et PKCE.
[DYNAMIQUE] POST    {token_endpoint}
          URL dynamique obtenue par OpenID Discovery; échange le code, renouvelle ou révoque selon les capacités annoncées.
[DYNAMIQUE] GET     {end_session_endpoint}
          URL dynamique obtenue par OpenID Discovery; ferme la session du compte client.
[REST HÉRITÉ] GET     https://{shop}.myshopify.com/admin/api/2026-07/storefront_access_tokens.json
          Liste les jetons Storefront créés par l'application.
[REST HÉRITÉ] POST    https://{shop}.myshopify.com/admin/api/2026-07/storefront_access_tokens.json
          Crée un jeton d'accès Storefront.
[REST HÉRITÉ] DELETE  https://{shop}.myshopify.com/admin/api/2026-07/storefront_access_tokens/{storefront_access_token_id}.json
          Supprime un jeton Storefront.

2. ENDPOINTS GRAPHQL CENTRAUX
====================================================================================================
[ACTUEL] POST    https://{shop}.myshopify.com/admin/api/2026-07/graphql.json
          Endpoint unique de l'Admin GraphQL API. Sert à lire et modifier produits, commandes, inventaire, clients, contenu, marchés, webhooks, remises, paiements et paramètres.
[ACTUEL] POST    https://{shop}.myshopify.com/api/2026-07/graphql.json
          Endpoint unique Storefront GraphQL pour construire une vitrine, rechercher le catalogue et gérer les paniers.
[ACTUEL] POST    https://{shop}.myshopify.com/customer/api/2026-07/graphql
          Endpoint Customer Account GraphQL pour le profil du client, ses adresses, commandes, retours et consentements.
[ACTUEL] POST    shopify://customer-account/api/2026-07/graphql.json
          Pseudo-URL disponible uniquement dans une extension Customer Account UI; Shopify gère automatiquement l'authentification.
[SPÉCIALISÉ] POST    https://partners.shopify.com/{organization_id}/api/2026-04/graphql.json
          Partner API : données du tableau de bord Partner, revenus et événements d'applications. Ce n'est pas l'API principale de gestion d'une boutique.
[SPÉCIALISÉ] POST    https://shop.app/api/partners/graphql.json
          Shop Partners API : gère les définitions de métachamps et données partenaires de Shop.

19. NOTES D'IMPLÉMENTATION POUR LE PROJET SHOPIFY AI COMMERCE ORCHESTRATOR
====================================================================================================
- Utiliser ADMIN GRAPHQL 2026-07 comme voie principale.
- Conserver REST uniquement derrière un adaptateur de compatibilité pour les ressources encore nécessaires.
- Ne jamais stocker le jeton Admin, le secret webhook ou les clés fournisseur dans le code ou dans ce fichier.
- Valider les scopes à la connexion avec /admin/oauth/access_scopes.json et avec les capacités GraphQL.
- Utiliser les webhooks pour commandes payées, remboursements, inventaire, exécution et suivi plutôt que
  de faire uniquement du polling.
- Pour le flux fournisseur Alibaba prévu : ne passer la commande fournisseur qu'après confirmation
  vérifiée du paiement Shopify; conserver l'adresse client de façon sécurisée; transmettre le suivi
  à Shopify dès qu'il est disponible; appliquer le pourcentage de profit configuré dans .env.
- Pour les opérations volumineuses, utiliser bulkOperationRunQuery et bulkOperationRunMutation.
- Pour les thèmes, préférer themeFilesUpsert/themeFilesDelete à l'ancien Asset REST lorsque disponible.
- Pour les produits, utiliser productSet et les mutations bulk de variantes plutôt que Product REST.
